# MSPM0G3507 双轮小车控制工程

基于 TI MSPM0G3507、DriverLib 和裸机主循环，实现双轮差速小车的速度 PI 闭环、四路红外巡线、按键控制及串口调参。工程从 SDK 的 `empty` 示例扩展而来，CCS 工程名仍为 `empty_LP_MSPM0G3507_nortos_ticlang`。

电机 PWM 由外部串口驱动板输出，编码器速度也由驱动板上报；MSPM0 负责计算左右轮目标速度和 PI 输出，不直接采集编码器脉冲。

> `APP/line.c` 的 `Line_Read()` 使用 `uint32_t` 保存 GPIO 原始位掩码，再转换为黑线检测值，避免 PA24～PA27 的高位被截断；实际接线、传感器电平及循迹效果仍需实车验证。

## 功能与默认参数

| 项目 | 当前实现 |
| --- | --- |
| 运行方式 | 裸机主循环，无 RTOS；SysTick 提供 1 ms 时基 |
| 速度档位 | 150 / 300 / 600 mm/s，上电默认 150 mm/s |
| 速度控制 | 左右轮独立 PI，新有效速度反馈帧到达时更新 |
| PI 初值 | `Kp = 1.5`，`Ki = 8.0`，无微分项 |
| 输出限幅 | PWM：±3600；积分项：±1800 |
| 巡线 | 默认开启，20 ms 更新一次；黑线低电平有效 |
| 巡线系数 | `Kp = 0.1`，转向修正限幅为基础速度的 ±30% |
| 停车条件 | 按键停止、反馈失效或控制更新间隔超过 300 ms；巡线全白/全黑时停车等待，连续 3 次有效检测后自动恢复 |
| 上位机遥测 | 每 60 ms 检查并发送四路速度或反馈异常标记 |

## 硬件连接

需要兼容下述串口协议的电机驱动板、带编码器的左右电机、四路数字红外巡线模块和三个低电平有效按键。驱动板具体型号未在源码中明确，接入前需核对协议、供电及逻辑电平，并使各模块共地。

### 引脚分配

| 功能 | 外设 / 信号 | MCU 引脚 | 连接说明 |
| --- | --- | --- | --- |
| 电机驱动板串口发送 | UART1 TX | PB6 | 接驱动板 RX |
| 电机驱动板串口接收 | UART1 RX | PB7 | 接驱动板 TX |
| PC 串口发送 | UART0 TX | PA10 | XDS110 USB 回传通道 |
| PC 串口接收 | UART0 RX | PA11 | XDS110 USB 回传通道 |
| K1 | GPIO 输入，上拉 | PA2 | 按下接地，启动 / 停止 |
| K2 | GPIO 输入，上拉 | PB19 | 按下接地，运行时换挡 |
| K3 | GPIO 输入，上拉 | PB20 | 按下接地，切换巡线 |
| 巡线 S0 | GPIO 输入 | PA24 | 权重 +3 |
| 巡线 S1 | GPIO 输入 | PA25 | 权重 +1 |
| 巡线 S2 | GPIO 输入 | PA26 | 权重 −1 |
| 巡线 S3 | GPIO 输入 | PA27 | 权重 −3 |
| 状态输出 | GPIO 输出 | PB2 | 代码实例名为 `LED1`，巡线开启时每轮主循环翻转 |
| SWD 时钟 / 数据 | SWCLK / SWDIO | PA20 / PA19 | 连接 XDS110 |

两路 UART 均为 **115200 baud、8 数据位、无校验、1 停止位、无硬件流控（8N1）**。

- K1/K2/K3 是本工程的按键定义，不对应 LaunchPad 自带的 S1/S2；三个按键均有 20 ms 按下及松开消抖。
- PB2 是本工程配置的状态输出，并非 LaunchPad 板载 LED1 所在的 PA0。翻转没有固定周期，不能据此判断控制周期。
- 使用 LaunchPad 的 XDS110 回传串口时，J21/J22 应处于 `[1:2]`，在电脑端选择 `XDS110 Class Application/User UART`。
- PA26、PA27 与 LaunchPad 板载光传感器电路相连，外接巡线模块时应移除对应的 J18、J17 跳线，避免电路干扰。
- S0～S3 的物理排列和轮子正方向需通过实车验证，使偏差与差速修正方向一致。

### 电机通道

驱动板协议按四个通道传输，软件数组按 **0～3** 索引：

| 车轮 | 软件索引 | 四通道报文位置 |
| --- | --- | --- |
| 左轮 | `LEFT_MOTOR_ID = 1` | 第 2 项 |
| 右轮 | `RIGHT_MOTOR_ID = 3` | 第 4 项 |

正常闭环仅更新上述两路，其余两路输出为 0。不要将数组索引 `1 / 3` 误解为报文第 1 / 3 项；更换接线时同步修改 `APP/motor.h`。

## 编译、手动烧录与首次运行

1. 安装上表中的 SDK、编译器及 SysConfig，在 CCS 中导入本目录下含 `.project` 的工程；不要导入历史 ZIP 备份。
2. 检查工程的产品依赖，确认 SDK 和 SysConfig 指向本机安装位置；工程引用了 SDK 中的启动代码和 DriverLib，不能只复制 `APP/` 与 `BSP/` 独立编译。
3. 选择 `Debug` 配置，执行 **Build Project**，确认编译、链接及 HEX 转换成功。供烧录使用的文件为 `Debug/empty_LP_MSPM0G3507_nortos_ticlang.hex`；同名 `.out` 用于链接及调试。检查 HEX 存在且非空，并结合构建日志和文件更新时间确认产物；构建失败时不要将残留旧 HEX 当作本次更新。
4. 用户通过 **UniFlash 手动烧录**上述 HEX 文件。默认由助手完成编译和 HEX 路径交付，到此结束；烧录及后续运行由用户操作，不自动启动 CCS 调试下载或操作 UniFlash。
5. 打开 PC 串口，设置为 `115200 / 8N1`、无流控。程序启动时输出 `...start...`，并向驱动板发送停车指令和 `$upload:0,0,1#`。
6. 确认驱动板已持续返回有效 `$MSPD:...#` 速度帧。未收到过有效反馈时，按 K1 会立即触发反馈保护停车；正常运行时反馈间隔应显著小于 300 ms。
7. 首次调试先架空车轮，可在待机状态按 K3 关闭巡线，再按 K1 验证速度闭环。确认巡线电平、排列和方向后，再开启巡线测试。

### 按键操作

| 按键 | 待机 / 停止时 | 运行时 |
| --- | --- | --- |
| K1 | 清除 PI 状态并启动 | 清除 PI 状态并停车 |
| K2 | 无操作 | 按 150 → 300 → 600 → 150 mm/s 循环换挡 |
| K3 | 切换巡线开关 | 切换巡线；关闭后恢复当前档位的直行目标速度 |

上电默认处于等待状态，巡线开启。运行中全白或全黑时立即停车等待，仍每 20 ms 检测；连续 3 次检测到有效线型（1～3 路黑线）后按当前档位自动恢复循迹，中途再次全白/全黑会清零恢复计数。停车等待期间 K1 取消运行及自动恢复，K2 更换恢复时使用的档位但保持停车，K3 关闭巡线后按当前档位直行。等待期间持续检查反馈；反馈失效或控制更新间隔超过 300 ms 会转为故障停车，即使线型和反馈随后恢复，也需按 K1 重新启动。手动停止同样不会自动启动。停止后保留当前档位及巡线开关，复位后恢复默认值。

## 串口协议

### PC 调参（UART0）

命令以 `$` 开始、`#` 结束，使用 ASCII 文本；无需追加换行，末尾的 `\r\n` 会被忽略。数值和 `#` 之间不要添加额外字符。接收缓冲区最多容纳 31 个正文字符，超长帧丢弃。

| 命令 | 示例 | 合法范围 | 成功响应 |
| --- | --- | --- | --- |
| 设置速度 PI | `$PI:1.5,8.0#` | `Kp`、`Ki` 均为 0～100 | `PI:OK` |
| 设置巡线比例系数 | `$LINEKP:0.1#` | 0～1 | `LINEKP:OK` |

设置 PI 时会更新全部四个控制器并清除积分。未知、格式错误或越界命令没有错误响应。参数仅保存在 RAM，复位后恢复源码初值。PC 命令目前仅支持这两种调参，不支持通过串口启动、停车或选择档位。

### PC 遥测（UART0）

启动提示后，每 60 ms 输出一行四通道实际速度，单位为 mm/s，格式如下：

```text
0.0,150.0,0.0,150.0
```

每行以 `\r\n` 结束；调参响应也会出现在同一串口流中，上位机解析时应将其与速度数据区分。没有有效速度反馈或反馈超过 300 ms 未更新时，输出 `eeeeeeeeeeeee`，不继续发送旧速度。遥测在待机、运行和停止状态均会执行。

### 电机驱动板协议（UART1）

| 方向 | 格式 / 命令 | 用途 |
| --- | --- | --- |
| MCU → 驱动板 | `$pwm:p0,p1,p2,p3#` | 四通道 PWM，每项限幅到 −3600～3600 |
| MCU → 驱动板 | `$pwm:0,0,0,0#` | 停车 |
| MCU → 驱动板 | `$upload:0,0,1#` | 启动时请求速度上报，具体字段语义以驱动板协议为准 |
| 驱动板 → MCU | `$MSPD:v0,v1,v2,v3#` | 四通道实际速度，单位 mm/s |

例如：`$MSPD:0,150,0,150#` 对应左、右轮速度均为 150 mm/s。接收端要求恰好四个数值，各项在 −100000～100000 范围内；无效帧不会刷新反馈有效时间。帧从 `$` 到 `#` 之前最多保存 63 个字符。

`Motor_Config310()` 还定义了以下驱动板配置，但 **`main()` 当前未调用**，不能认为上电会自动完成电机标定：

```text
$mtype:2#
$mphase:20#
$mline:13#
$wdiameter:48#
$deadzone:1600#
```

使用这些配置前，应按实际电机、编码器、轮径及驱动板文档核对；速度单位及精度依赖驱动板的正确配置。

## 控制逻辑与修改入口

主循环依次处理驱动板反馈、按键、巡线、速度 PI、PC 遥测和 PC 命令。速度闭环随新反馈帧更新，`dt` 由实际经过的毫秒数换算为秒；巡线采用 20 ms 周期。

巡线按以下公式计算，其中 `s0`～`s3` 表示是否检测到黑线（是为 1）：

```text
count = s0 + s1 + s2 + s3
line_offset = (3*s0 + s1 - s2 - 3*s3) / count
turn = clamp(base_speed * line_kp * line_offset, -0.3*base_speed, 0.3*base_speed)
left_target  = base_speed - turn
right_target = base_speed + turn
```

`count` 为 0 或 4 时立即发送零 PWM、清除 PI 积分并停车等待，不执行偏差计算；恢复计数清零。随后连续 3 次有效检测才重新计算偏差并恢复目标速度，前两次仍保持零目标和零 PWM。等待期间主循环继续处理反馈、按键、遥测及调参，速度 PI 随新反馈更新零输出，不累积积分；反馈保护保持有效。K1 启动或 K3 切换模式会重置恢复计数，新启动时若线型有效可立即循迹。当前没有交叉口识别或主动丢线搜索；停住后需让传感器重新检测到有效线型才能自动继续。

| 需要修改的内容 | 位置 |
| --- | --- |
| 档位速度、PI 初值、巡线周期、主循环反馈保护 | `empty.c` |
| 左右轮通道 | `APP/motor.h` |
| PI 算法与积分 / PWM 限幅 | `APP/pid.c`、`APP/pid.h` |
| 黑线电平、巡线权重、默认系数与转向限幅 | `APP/line.c` |
| 遥测周期、PC 命令与遥测反馈超时 | `APP/telemetry.c` |
| 按键消抖 | `BSP/bsp_key.c` |
| 驱动板 UART 缓冲区、发送等待上限 | `BSP/bsp_uart.c` |
| 引脚、串口、时钟与 SysTick | `empty.syscfg`（通过 SysConfig 修改并重新生成） |

反馈超时阈值分别出现在主循环和遥测模块，调整时需同步检查。`UART_GetOverflowCount()` 可用于观察驱动板接收环形缓冲区的丢字节情况。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 按 K1 后马上停止 | 是否已有新鲜速度反馈；默认巡线是否触发全白 / 全黑；检查传感器电平、接线及 J18/J17 跳线 |
| PC 输出 `eeeeeeeeeeeee` | 检查驱动板供电、UART1 TX/RX 交叉连接、共地、波特率和 `$MSPD:...#` 格式 |
| PC 串口无输出或乱码 | 检查 User UART 端口、J21/J22、115200 / 8N1；确认程序已继续运行 |
| 只能一侧转动或速度反馈通道不符 | 检查第 2 / 4 通道接线、左右轮映射和电机转向 |
| 巡线修正方向相反 | 检查 S0～S3 排列、黑线输出电平及左右轮映射 |
| 按 LaunchPad 自带按键无反应 | 本工程按键接在 PA2 / PB19 / PB20，需按接线表连接 |
| 调参复位后丢失 | 当前没有 Flash 参数持久化，请修改源码默认值或启动后重新下发命令 |
| 编译提示缺少 SDK 或 SysConfig | 在 CCS 中安装并关联工程引用的产品版本，检查本机依赖路径 |
